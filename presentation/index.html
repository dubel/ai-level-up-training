SZYBKI POMIAR · RĘKA W GÓRĘ

Co faktycznie robisz co tydzień?

  1. 1Autocomplete i pojedyncze pytania
  2. 2Agent czyta kilka plików i proponuje zmianę
  3. 3Agent implementuje, testuje i poprawia
  4. 4Zespół ma wersjonowane rules / skills / workflow
  5. 5Agent używa narzędzi i pracuje z gotowej specyfikacji

Poziom jest per proces. Możesz być na 5 dla testów i na 1 dla zmian IAM.

1

CHAT

„Napisz mi…”

Snippety, wyjaśnienia, refactoring ideas.

Kontrola: człowiek kopiuje i ocenia każdy wynik.
2

CONTEXT-AWARE

„Zrozum mój kod.”

Agent szuka wzorców, historii i testów w repozytorium.

Nowa kompetencja: wybór właściwego kontekstu, nie większego kontekstu.
3

AGENTIC

„Zrób zmianę.”

Plan → wiele plików → terminal → testy → diff.

Zmiana roli: delegujesz wynik, a nie następną linię kodu.
4

RULES + SKILLS

„Pracuj po naszemu.”

Stałe zasady i procedury żyją w repo, nie w pamięci jednej osoby.

Efekt: mniej powtarzania, mniej dryfu, szybszy onboarding.
5

TOOLS + MCP

„Sprawdź stan świata.”

Dokumentacja, Jenkins, Git, AWS, vSphere — w granicach uprawnień.

Reguła: im silniejsze narzędzie, tym mocniejsza granica akceptacji.
6

SPEC + TEAM

„Zrealizuj kontrakt.”

Problem → spec → plan → implementacja → testy → review.

Skalowanie: większa autonomia jest skutkiem lepszego kontraktu.

COST + PERFORMANCE

Mniej hałasu.
Więcej sygnału.

Optymalizujemy pracę agenta, nie tylko cenę pojedynczego tokena.

MODEL KOSZTU

Retry i powtarzany kontekst bolą podwójnie.

input+output+tool calls+repeated context+retries
  • Wybieraj najwęższy test i fragment logu.
  • Nowa rozmowa po zakończeniu logicznego zadania.
  • Mocny model do decyzji; tańszy do mechanicznej egzekucji.
  • Mierz wynik i czas review, nie samą liczbę tokenów.

TRZY RÓŻNE DŹWIGNIE

Nie kompresują tego samego.

RTKterminal → input

Filtruje hałaśliwy output komend, zanim zobaczy go model.

Cavemanagent → output

Skraca prozę odpowiedzi, zachowując techniczny konkret.

Ponytaildecyzja → code

Wymusza najprostsze rozwiązanie i aktywnie szuka kodu do usunięcia.

RTK raportuje redukcję outputu shell, nie całego rachunku. Caveman może być stratny przy już krótkich odpowiedziach.
