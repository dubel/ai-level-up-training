# Laboratoria Cursor

Każdy katalog jest niezależnym, małym repo-demo. Otwieraj go jako osobny folder w Cursorze, aby reguły, skills, hooks i MCP nie wpływały na inne ćwiczenia.

| Demo | Temat | Czas | Wymaga instalacji |
|---|---|---:|---|
| `01-prompt-context` | ten sam task: prompt vs kontrakt + rule | 20–30 min | nie |
| `02-rules-skills-hooks` | rule vs skill vs hook | 30–40 min | nie |
| `03-rtk` | hałas terminala przed/po | 10 min | RTK opcjonalnie |
| `04-caveman` | krótszy output agenta | 8 min | nie; upstream opcjonalnie |
| `05-ponytail` | mniej kodu, mniej abstrakcji | 12 min | nie; upstream opcjonalnie |
| `06-context7` | odpowiedź z pamięci vs aktualne docs | 15–20 min | Context7 dla pełnego demo |
| `07-bmad-quick-flow` | spec → dev → testy → review | 30 min | nie |
| `08-prompt-injection` | niezaufany dokument i approval boundary | 10 min | nie |

## Zasada resetu

Przed drugim przebiegiem cofnij wyłącznie zmiany wykonane w danym demo (`Review changes` w Cursorze lub świeża kopia katalogu). Nie resetuj całego repozytorium szkoleniowego.

## Wspólne skróty prowadzącego

- Najpierw poproś o **plan bez edycji**.
- Pokaż uczestnikom listę plików i komend, które agent zamierza użyć.
- Dopiero potem zatwierdź implementację.
- Review wykonuj w diffie, nie na podstawie podsumowania agenta.
