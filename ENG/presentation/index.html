QUICK CHECK · SHOW OF HANDS

What do you actually do every week?

  1. 1Autocomplete and isolated questions
  2. 2An agent reads several files and proposes a change
  3. 3An agent implements, tests, and corrects
  4. 4The team versions rules, skills, and workflows
  5. 5An agent uses tools and works from an approved spec

The level is process-specific. You can be at 5 for testing and at 1 for IAM changes.

1

CHAT

“Write this for me…”

Snippets, explanations, refactoring ideas.

Control: a human copies and evaluates every output.
2

CONTEXT-AWARE

“Understand my code.”

The agent finds patterns, history, and tests in the repository.

New capability: selecting the right context, not more context.
3

AGENTIC

“Make the change.”

Plan → multiple files → terminal → tests → diff.

Role shift: delegate the outcome, not the next line of code.
4

RULES + SKILLS

“Follow our way of working.”

Permanent guidance and procedures live in the repository, not in one person's memory.

Result: less repetition, less drift, faster onboarding.
5

TOOLS + MCP

“Check the current state.”

Documentation, Jenkins, Git, AWS, and vSphere within explicit permissions.

Rule: the more powerful the tool, the stronger the approval boundary.
6

SPEC + TEAM

“Deliver against the contract.”

Problem → spec → plan → implementation → tests → review.

Scale: more autonomy follows from a better contract.

BEFORE / AFTER

Precision removes guesswork.

BEFOREAdd retries to the deployer.

The model chooses scope, pattern, limits, and tests.

AFTERAdd at most two retries for transient errors only. Follow RetryPolicy. No new library. Add tests and run the test file.

The agent makes implementation decisions, not product decisions.

INDIRECT PROMPT INJECTION

05

COST + PERFORMANCE

Less noise.
More signal.

Optimize the agent's work, not just the price of one token.

COST MODEL

Retries and repeated context compound the cost.

input+output+tool calls+repeated context+retries
  • Choose the narrowest test and log excerpt.
  • Start a new conversation after a logical task is complete.
  • Use a strong model for decisions; a cheaper one for mechanical execution.
  • Measure outcomes and review time, not token count alone.

THREE DIFFERENT LEVERS

They do not compress the same thing.

RTKterminal → input

Filters noisy command output before the model sees it.

Cavemanagent → output

Shortens response prose while preserving technical substance.

Ponytaildecision → code

Forces the simplest solution and actively looks for code to remove.

RTK reports reductions in shell output, not the whole bill. Caveman can cost more when an answer is already short.
